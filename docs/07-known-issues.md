### 备份操作方式

- 已修正风险：SQLite 使用 WAL 时，活动中只复制主 `.db` 可能只得到不完整文件，原位恢复还可能受陈旧 `.db-wal`/`.db-shm` 影响。
- 推荐：使用 `sqlite3 .backup` 或核心 `SqliteStore::backup_to`（`VACUUM INTO`）生成一致性快照，并对快照执行 `PRAGMA integrity_check`。
- 侧车文件：恢复前必须停止服务，并处理目标路径下属于旧数据库的 `.db-wal`/`.db-shm`；不要把它们与新主文件混合。

## 直播数据统计限制

- 粉丝侧无法获取主播后台的官方营收和付费指标；页面展示的是公开礼物、SC、舰长事件估算。
- “最高同时在线”取公开 `ONLINE_RANK_COUNT.online_count` 事件的峰值，与主播后台官方“高能”统计可能存在口径差异。直播间人气/热度不再采集或展示。
- 未登录时，弹幕配置优先使用旧版 `room/v1/Danmu/getConf`，失败时回退 WBI 接口；已登录时使用带 Cookie 的 WBI 接口，不回退匿名 token。WebSocket 退避只在认证成功后重置，防止风控期间高频重连。
- 弹幕 WebSocket 与普通 HTTP 请求复用同一代理配置：显式代理端口优先，其次读取 `HTTPS_PROXY`/`ALL_PROXY`；当前仅支持 HTTP CONNECT 代理。仅放行 HTTP API、未放行 WebSocket 的出网环境仍会表现为事件类指标采集失败。
- 服务端弹幕连接使用单 socket 认证与事件循环，并在认证成功后立即发送心跳。已登录时，token、账户 UID 和 buvid 使用同一份 Cookie 快照；登录/退出后，现有连接会在下一次检查点（最长约 30 秒）重新认证。已配置但失效的 Cookie 会报告采集失败，不静默降级为匿名身份。登录态连接在数据中心出口仍可能遇到网关风控，需用部署环境验证。
- 原始弹幕、礼物和 SC 事件只在内存聚合，不写入数据库；应用崩溃或断网期间的事件无法补回。
- 跨应用重启时，付费用户和互动用户集合不持久化，唯一人数可能与整场真实值有少量偏差。
- 付费用户优先读取事件顶层 `uid`，为 `0` 或缺失时补读 `sender_uinfo.uid` / `uinfo.uid`；不使用收礼人的 UID。无法识别发送者的付费事件仍计入营收，不计入人数，并将数据质量标为不完整；不能用昵称或事件条数推算唯一付费人数。已漏采的历史用户标识无法从累计营收补回。
- `SEND_GIFT_V2`、盲盒活动和舰长价格仍需更多真实样本校验。
