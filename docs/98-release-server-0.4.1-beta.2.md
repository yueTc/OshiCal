# 推历 OshiCal 服务端 0.4.1-beta.2 测试版

## 相比 0.4.1-beta.1

- 修复 B 站转发联动公告时，日程房主找不到就错误使用参演主播房间的问题。已订阅的 A 参演即可收录 A 与 B 的联动，不要求先订阅 B，也不会自动添加 B。
- 房间优先使用公告中的有效直播间链接，也可通过房主 UID 或已知主播的唯一名称、别名匹配确认。确认不了时保留日程和已知房主信息，不填猜测的直播间，也不按参演主播和时间把这类日程并进其他场次。

## 产物与测试渠道

- GitHub 测试版标签为 `server-v0.4.1-beta.2`，签名更新清单发布到 `server-beta`。镜像为 `ghcr.io/yuetc/oshical-server:0.4.1-beta.2`，另附 Linux x86_64 `oshical-server-0.4.1-beta.2-linux-x86_64.tar.gz` 和 Windows x86_64 `oshical-server-0.4.1-beta.2-windows-x86_64.zip`，以及对应的 SHA-256 校验文件。
- 正式更新清单和 Docker `latest` 不变。使用宿主机更新代理时请保留现有签名校验配置，并在服务端设置中选择“测试版”；手动部署可固定此版本镜像或使用对应运行包。

## 升级前操作、限制与回退

- 相对上一测试版未新增数据库迁移、API 变更或必填环境变量。升级前请停服备份 SQLite 数据库及必要的 WAL/SHM、主密钥、`.env` 和更新代理配置，保留上一版本镜像或运行包。
- 升级不批量清理已保存的错卡；必要时可按原公告逐条核对并手动更正。回退前先保留升级后的数据和主密钥，再固定上一版本；只有确有必要时才恢复升级前备份，以免丢失升级后的记录。
