# 推历 OshiCal 桌面端 0.3.23-beta.4 测试版

本版相对上一已发布测试版 `0.3.23-beta.2`，包含此前仅用于本地验证的 `0.3.23-beta.3` 界面改进，并调整同场直播的日程去重、补全 B 站转发动态的原作者上下文。共享核心变更同时适用于桌面本地采集与服务端采集。

## 新增、修复与体验变化

- 粉丝与 YouTube 订阅者变化弹窗固定标题和关闭按钮，隐藏内容区与历史明细的滚动条，保留滚轮、触控板、触摸滚动和历史表头吸顶。
- 主播库“更多”菜单新增“进入个人主页”，分别使用系统浏览器打开 B 站空间或 YouTube 频道。
- “设置 → 本设备设置 → 日程卡片”新增独立的日程类型与直播间归属胶囊开关，默认开启并保存在当前设备；时间线、日历均适用，切换配色时保留选择。

- 同一直播间、开始时间相差不超过 10 分钟的日程优先按直播间合并，不再要求参与者名字必须重合；适用于开播补录卡没有参与者、团播预告由另一个账号发布等情况。
- 直播间不同的日程不会仅因参与者重合而合并；同一直播间不同时间段仍分开保留，两个已绑定独立直播场次的卡片不自动合并。
- 开播绑定和迟到预告匹配支持其他账号发布、但指向当前直播间的预告。明确的跨账号绑定可在前端显示“直播中”；旧服务端未提供明确绑定时仍按原有主播范围匹配。
- 合并重复卡片时迁移开播绑定和统计场次引用，保留来源；已有人工作出的锁定受到保护，预告标题和计划时间优先于开播补录内容。
- B 站转发动态分析纳入原动态发起人昵称、MID、动态编号、链接、发布时间、正文及预约卡，合并可用图片；区分原文与转发附言，不把转发者自动当成参与者或直播间主人。

## 数据、配置与兼容性

- 胶囊显示偏好仅保存在本设备，旧配置缺少字段时默认开启，不改变服务端配置或同步至其他设备。
- 无新增数据库表、迁移、环境变量或 API 字段，同步 schema 保持不变。共享核心同时更新快照导入校验，使同直播间的跨账号卡片绑定可以导出后重新导入；需要此能力时建议两端配套升级。
- 动态分析缓存版本更新为 post-v5。后续刷新可能重新分析已缓存的动态，增加一次性模型调用及费用；原作者上下文变化也会使相应缓存失效。
- 不直接修改现有用户数据库。已有重复数据在更新后执行正常采集刷新时进入去重；不按房间全局删除历史场次。

## 下载、安装与渠道

- 版本与标签：`0.3.23-beta.4` / `desktop-v0.3.23-beta.4`。发布时 Release 必须标记 prerelease，维护固定 `desktop-beta` 清单，不移动正式更新清单。
- 普通用户下载 Windows x64 **NSIS 安装包**；已安装用户可在“设置 → 软件更新”中检查更新。
- 自动更新包使用 Tauri 签名校验；当前发布工作流未配置 Windows Authenticode 代码签名步骤，Windows 可能提示“未知发布者”，二者不是同一种签名。
- 构建、测试、签名和产物验证仅通过 GitHub Actions 或用户指定的外部构建机进行。本次源码准备未生成、覆盖或删除任何发布产物。

## 升级前操作、已知限制与回退

- 升级前退出客户端并备份完整数据目录、连接配置及凭据主密钥文件；连接服务端时也应先做服务端备份。
- 去重会合并来源并删除自动重复卡，若需恢复合并前的独立记录，应使用升级前数据库备份，单独回退程序不会拆回已合并的卡片。
- 转发原文已删除或不可用时，只保留可读取的转发附言；嵌套转发最多处理四层。模型识别仍沿用每条动态最多前两张图片的限制。
- 本机仅完成源码静态检查与格式检查；已补充回归用例，尚未执行 CI、真实采集回归或发布验证。本文件是发布正文草稿，发布前必须根据 CI 与产物验证结果定稿；正式版需另行确认。
