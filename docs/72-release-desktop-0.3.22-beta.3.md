# 桌面客户端 0.3.22-beta.3（测试版）

本版相对上一已发布的桌面测试版 0.3.22-beta.1，修复无预告开播误关联历史直播卡片，并补齐断流重连时的日程与统计关联。服务器模式建议同时升级服务端 0.3.30-beta.6。

## 新增与修复

- 主播没有发布预告直接开播时，自动生成“开播补录”日程，使用实际开播时间和直播间标题，下播后保留。已有昨天的卡片不会仅因“时间最近”而显示本场直播中。
- 先判断是否属于同一场直播，再关联卡片：平台开播时间未变时保留原场；同一直播间重置开播时间后，断流 30 分钟内（含边界）恢复仍合并为原场。跨午夜持续直播不另建卡片。
- 新场仅复用实际开播时间前后 2 小时内（含边界）的有效预告；无合适预告才补卡。取消、已被其他场次占用、明确属于其他直播间的卡片不被复用。
- 直播统计与日程使用相同的场次判定，重连后继续关联原卡片，保留累计统计；查看直播数据优先打开本卡片实际绑定的场次。
- 重复轮询、短暂请求失败和应用重启不会按每次检查时间重复补卡。平台暂时缺少开播时间时固定首次检测时间；之后补回平台时间不改变已绑定卡片。
- 自动补卡遵循主播的日程采集开关，不要求开启直播统计或开播通知。用户修改卡片不被轮询覆盖；删除或取消本场卡片后，本场不会自动恢复，也不会转而高亮其他预告。
- 开播后才采集到的同场预告会附加为来源，保留原卡片和用户修改。新增卡片通过现有同步流程自动显示，无需手动切换日历。

## 数据、接口与兼容性

- 共用 crates/core 新增轻量直播场次状态及卡片绑定，独立模式和服务端均使用此逻辑。数据库启动时增量迁移，不批量修改历史卡片，也不回填无法确认的历史场次关联。
- 直播状态和场次汇总增加可空的 scheduleId；同步协议版本不变。新桌面连接缺少该字段的旧服务端时，只采用前后 2 小时的有界兼容匹配，不保证旧服务端能补建无预告卡片。
- 客户端导出与导入覆盖轻量场次及卡片 ID 映射，旧快照缺少新增字段仍可读取。沿用原有迁移范围，不额外迁移历史统计采样。
- 无新增必填环境变量或运行时依赖。30 分钟内主动下播再开也可能合并为续播；提前或迟到超过 2 小时会保留原预告并另补本场卡片。上述阈值本版固定，不新增设置项。

## 升级与回滚

升级前备份客户端完整数据目录；服务器模式应先备份服务端数据库与配置，并配合升级服务端。在线 SQLite 应使用一致性备份，或停止程序后连同必要 WAL 一并保存，不要直接覆盖正在运行的数据库。

回滚前先保存当前完整数据，再安装旧版。旧程序不能识别新增场次关联，不提供本版补卡保证；如需恢复旧数据库，请使用升级前备份，备份后的新增数据将不在其中。本版不自动清理或重写旧日程。

## 下载与更新渠道

- 发布标签为 desktop-v0.3.22-beta.3，标记为 prerelease，仅更新 desktop-beta 测试版清单，不替换桌面正式版 latest。
- 普通用户下载 Windows x64 NSIS 安装包（.exe）；已安装用户可在“设置 → 软件更新”选择测试版渠道并检查更新。其他产物以发布页实际附件为准。
- 自动更新包使用 Tauri 签名校验；当前发布流程未配置 Windows Authenticode 代码签名，Windows 可能提示未知发布者。
- 构建、回归、签名及发布通过 GitHub Actions 执行；正式版须另行确认。
