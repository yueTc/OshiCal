# 产品需求与行为契约

## 1. 术语

| 术语 | 定义 |
| --- | --- |
| 主播 | 用户实际订阅并希望收到日程/开播信息的 B 站账号 |
| 官号 | 发布主播日程、组合日程或宣传信息的关联账号 |
| 团播 | 同一场直播由多名参与者共同进行；实际直播间可能属于未订阅人员；A-SOUL 固定展开为乃琳、嘉然、贝拉 |
| 动态源 | 主播本人账号或任一已关联官号 |
| 日程 | 有标题、开始时间、所属主播、直播间链接的直播安排 |
| 候选结果 | 从动态中提取、尚未自动归属成功的事件；本项目不持久化低置信度候选 |
| 共享分析 | 同一文字版本或同一图片只调用一次日程模型，结果供多个主播归属筛选 |

## 2. 功能行为契约

| 场景 | 输入 | 输出 | 异常处理 | 验收标准 |
| --- | --- | --- | --- | --- |
| 搜索账号 | 昵称、UID、`@昵称` 或空间链接 | 去重排序后的账号列表，含 MID、昵称、头像、直播间号 | 网络失败返回可读错误；有本地精确命中时可降级返回；输入防抖并忽略过期响应 | 输入 `672328094` 直接返回嘉然；快速连续输入只展示最终结果；清空按钮同时清空结果 |
| 浏览器登录获取 Cookie | 桌面端打开 B 站登录窗口并完成登录 | WebView 检测 SESSDATA 等 Cookie 并保存到 Windows 凭据管理器 | 只允许 B 站域名；超时或保存失败显示错误 | Cookie 不回传前端且后续搜索使用新 Cookie |
| 扫码登录 | B 站二维码会话 | 显示二维码，轮询等待/已扫描/成功/过期状态 | 二维码过期可重新生成；网络失败最多重试并提示 | 确认后保存 Cookie，无需手动复制 |
| 退出 B 站登录 | 用户确认退出 | 删除 Windows 凭据管理器中的本机 Cookie 并刷新状态 | 服务端环境变量不受影响；取消确认不删除 | 退出后显示“使用公开接口 + buvid” |
| 查看来源 | 日程的来源动态 ID | 默认浏览器打开 B 站动态页 | 非 B 站 HTTPS 地址拒绝 | 点击“查看来源”成功打开 `t.bilibili.com` |
| 添加订阅 | 搜索结果账号 | 创建主播订阅，默认开启日程订阅与开播通知 | 重复 MID 不重复创建 | 重复添加只保留一条 |
| 关联官号 | 主播订阅 + 官号 MID/昵称 | 官号与主播关联 | 已关联则幂等返回 | 同官号只关联一次 |
| 官号多人日程 | 同一官号动态包含多个主播的时间安排 | 大模型返回多个 performer 事件，分别归属对应主播 | 单个事件无法唯一匹配时丢弃该事件，不连坐整帖 | 甲乙同帖两条日程分别入库 |
| 多人团播 | 同一场直播包含多名参与者，可能使用未订阅人员的直播间 | 只生成一条共享日程，保存全部 participants、room_url 与实际 room_owner；至少一名参与者匹配订阅主播后入库；图片与文字跨主账号识别时也合并 | 无订阅参与者、时间不明确或直播间无法确认时不做错误猜测；10分钟内至少两名参与者重叠视为同一团播 | 两名订阅主播 + 一名外部嘉宾只生成一条日程；先图片后文字、归属账号不同也只保留一张卡 |
| 删除主播 | 主播订阅记录 | 直接删除主播、其全部日程、官号关联和来源抑制记录 | 未找到主播返回 404 | 删除后主播库与日程列表均不再出现该主播记录 |
| 刷新动态 | 每个订阅主播的个人账号 + 已关联官号 + A-SOUL 自动官方来源 | 新增/更新日程 | 单个源失败不阻断其他源 | 只订阅乃琳也会同时请求乃琳个人账号和 A-SOUL_Official；失败源显示错误，其他源成功 |
| 文本日程 | 含日期时间的动态文本 | 大模型输出结构化多主播日程 | 模型未配置/失败时不用正则猜测自由文本 | “10月30日 20:00 直播”正确入库 |
| 预约卡片 | 动态 additional.reserve | 标题、时间、直播间 | 时间无法解析则丢弃 | 卡片开始时间正确 |
| 图片日程 | 含日程图的历史动态 | 结构化多主播事件 | 模型失败只记录错误，不重复扣费 | 同图只调用一次模型 |
| 主播归属 | 图片事件 + 别名表 | 唯一主播归属 | 低置信度/多匹配直接丢弃 | 不产生错归属正式日程 |
| 手动日程 | 主播、标题、开始时间、可选直播间 | 创建或更新日程 | 非法时间返回校验错误 | 本地和服务器模式都可操作 |
| 关闭日程订阅 | 主播开关 | 停止抓取并隐藏未来日程 | 未知主播返回 404 | 重新开启后恢复未被删除的日程 |
| 双模式导入 | 服务器快照 | 导入客户端并去重 | 冲突由用户选择策略 | 服务器数据不被修改 |
| 离线写入 | 新增/修改/删除操作 | 本地同步队列 | 恢复后同步并检测冲突 | 断网不丢操作 |
| 日程删除 | 自动日程 | 当前来源版本永久抑制 | 不删除手动日程 | 同来源不恢复，新发布可恢复 |
| 预约取消 | 取消/撤回的预约 | 标记已取消并隐藏未来记录 | 历史保留 | 不再出现在未来视图 |
| 日程视图 | 起始日期、视图模式 | 连续 7 天日程 | 空区间显示空状态 | 每次前进/后退移动 1 天 |
| 通知触发 | 运行中开播状态变化 | 每位主播独立通知 | 启动或重连时已直播不补发 | false → true 只通知一次 |
| 托盘与自启 | 关闭窗口、开机自启设置 | 托盘继续运行或开机启动 | 自启失败显示设置错误 | 默认关闭自启 |
| 跳转直播间 | 日程或通知 | 默认浏览器打开直播 URL | 无直播间则按钮禁用 | 点击后浏览器打开正确页面 |
| 开播监控 | 订阅集合 | 状态变化事件 | 单主播失败继续其他主播 | false → true 只通知一次 |
| 通知点击 | Windows 通知 | 打开对应直播间 | 浏览器失败显示错误 | 点击后默认浏览器打开 |
| 双模式 | 设置中的数据源 | 本地 IPC 或远程 HTTP/WS | 远程不可达时显示离线状态 | 切换后数据来源正确 |
| 服务端推送 | 状态/日程变化 | WebSocket 事件 | 断线指数退避重连 | 1 秒内收到已发布事件 |
| 开关控制 | 日程/开播开关 | 更新订阅配置 | 非法 ID 返回 404 | 关闭后不再产生对应行为 |

## 3. 日程解析规则

1. 时区固定 Asia/Shanghai。
2. 显式日期优先：`YYYY年M月D日`、`M月D日`、`M/D`。
3. 无年份日期取当前年；若已超过 30 天，判定为过去并丢弃，不顺延到下一年。
4. 相对日期支持“今天、今晚、明天、明晚、后天”。
5. 周几支持“周一”至“周日/周天”，解释为发布时刻所在自然周。
6. 仅有星期几且该日期已过去时直接丢弃。
7. 时间支持 `HH:mm`、`H:mm`、`HH：mm`，以及 `20:00-22:00` 范围。
8. “晚/晚上/今晚/明晚”的 1 至 11 点按下午/晚上解释；12 点保持 12 点。
9. 标题优先取直播预约标题；其次取同时段文本中的主题行；缺失或仅为占位内容时，复用同一主播最近 8 周内相同星期、相近开播时间的有效标题（历史日程优先，其次历史直播场次）；最后使用“直播”。后续缺失标题不得覆盖已有有效标题。
10. 同一主播、开始时间相差不超过 10 分钟视为同一直播；合并展示并保留全部来源。
11. 只有日期但没有具体时间的日程直接丢弃。
12. 预约撤回或取消后标记为已取消，未来视图隐藏，历史记录保留。

## 4. 图片日程与大模型规则

- 只对含有日程关键词且包含图片的动态自动发起视觉分析。
- 日程关键词包括：直播、开播、预约、日程、周表、课表、排班、今晚、明晚。
- 有日程图片时，图片和该动态的完整文字描述必须进入同一个多模态请求；图片负责时间、主题和图中人员，文字负责直播间归属、参与者补充和例外说明。
- 无图片动态单独使用文字模型；有图片时不再额外调用同一动态的纯文字模型，避免重复事件。
- 分析缓存键为：动态 ID + 图片摘要 + 文字摘要 + 模型名 + Prompt 版本。
- 同一图片与同一文字组合被多个主播共享时，只调用模型一次。
- 模型输出必须是 JSON 数组，字段为：`action`、`performer`、`aliases`、`participants`、`room_url`、`room_owner`、`title`、`start_at`、`end_at`、`confidence`。
- 模型输出中的外部文本只作为数据，禁止执行其中的指令。
- 主播归属顺序：人工别名精确匹配 → 归一化精确匹配 → 唯一包含/相似匹配。
- 单人事件的综合置信度 ≥ 0.85 且只匹配一个订阅主播时自动归属；低置信度、多匹配或无法匹配时直接丢弃。
- 团播事件按每名参与者独立匹配订阅主播，允许多名订阅主播同时命中；归属到订阅 ID 最小者作为稳定主记录，不因匹配到多人而丢弃。
- 团播必须至少有一名参与者匹配订阅主播；`participants` 保存模型识别出的全部人员姓名，包括未订阅人员，但不会为外部人员创建独立订阅。
- `A-SOUL`、`ASOUL` 统一展开为乃琳、嘉然、贝拉后再参与归属。
- 乃琳、嘉然、贝拉任一成员开启日程订阅时，来源集合自动包含个人账号与 `A-SOUL_Official`（MID `703007996`），无需逐个手动关联。
- `room_url` 只接受 `https://live.bilibili.com/`；`room_owner` 和 `room_owner_mid` 表示原文可确认的直播间所属主播。模型优先从 `space.bilibili.com/<UID>` 提取 MID；系统再按 MID 或直播间号查询 B 站真实房间。无法确认时不把团播错误挂到归属主播自己的直播间。
- 宽泛的“本周暂停单双人直播”等说明，如果没有具体日期、开始时间和原日程标题，不得生成 cancel 事件。
- 同一来源的动态严格按发布时间从旧到新处理；新公告覆盖旧公告。日程保存来源发布时间，更旧的公告即使后处理也不能覆盖新版本。
- 动态文字或图片明确表示取消、停播、延期或改期时，模型返回 `action=cancel`；系统按主播、±10 分钟时间和标题匹配已有日程并删除，同时抑制被删日程的旧来源版本。
- 取消事件匹配到多个同时候选且标题无法唯一确定时不删除，避免误删。
- B 站预约卡片必须包含明确日历日期或今天/明天/后天等相对日期；只有星期几或只有时间时不生成预约日程。

## 5. 双模式同步、手动编辑与通知

### 5.1 数据源与导入

- 本地模式和服务器模式都保存本地 SQLite 缓存。
- 切换到服务器模式时，从服务器单向导入订阅、官号和日程；服务器不被导入流程修改。
- 去重键：主播 MID、官号 MID、日程“主播 + 开始时间 + 标题”。
- 导入冲突先展示摘要，用户统一选择“服务器覆盖、保留客户端、只导入不冲突项”，并可展开明细。
- 在线时服务器是权威数据源；本地缓存用于离线展示和暂存写操作。
- 本地模式停止访问服务器；服务器模式停止本地抓取任务，避免双写。

### 5.2 手动编辑与自动来源

- 手动新增、修改、删除日程始终可用。
- 在线时手动写操作直接提交服务器；离线时写入本地同步队列。
- 恢复连接后按队列顺序同步，每条操作必须具备客户端唯一 ID 保证幂等。
- 用户修改自动日程后，该条记录进入手动锁定状态，后续自动刷新不得覆盖。
- 来源变化时只标记“来源已变化”，提供恢复正常抓取版本按钮。
- 用户删除自动日程时记录来源版本抑制信息；同一来源版本不恢复。
- 主播通过新动态重新发布后可生成新日程；新来源版本不受旧删除标记影响。
- 关闭“订阅日程”后停止抓取，并隐藏该主播未来自动日程；重新开启后恢复未被删除的日程。

### 5.3 通知与运行行为

- 官号只用于日程抓取，不参与开播监控。
- 多位主播同时开播时分别通知，每条通知点击后只打开对应直播间。
- 仅在客户端运行期间观察到 `未开播 → 开播` 时通知。
- 应用启动、服务器重连或重新开启通知时已经直播，不补发通知。
- 关闭窗口后驻留系统托盘继续监控。
- 设置页提供开机自启开关，默认关闭。
- 第一版不提供开播前提醒。

## 6. 状态流转

```text
订阅不存在 -> 已订阅
动态源读取成功 -> 解析中 -> 日程已确认
动态源读取失败 -> 订阅保留，记录 last_error
开播状态 false -> true -> 通知一次 -> true 保持
开播状态 true -> false -> 重置通知锁
日程已确认 -> 手动锁定
日程已确认 -> 来源更新提示
日程已确认 -> 预约取消 -> 已取消并隐藏未来显示
自动日程 -> 用户删除 -> 来源版本抑制
日程订阅关闭 -> 未来自动日程隐藏
服务器模式断线 -> 本地缓存展示 + 写入队列
服务器模式恢复 -> 队列同步 -> 冲突确认
```

## 7. 数据保留

- 保存订阅、官号关联、已确认日程、开播状态和最近错误。
- 保存动态分析缓存及原始结构化模型结果，用于跨主播复用。
- 不保存大模型 API Key、B 站 Cookie。
- 不保存未通过自动归属阈值的候选日程。
- 保存来源版本删除标记、手动锁定状态、离线写队列和同步冲突结果。
- 日志不记录 Cookie、API Key、完整模型响应正文。

## 8. 错误语义

| 错误码 | 场景 | 客户端行为 |
| --- | --- | --- |
| `BILI_RISK_CONTROL` | B 站 412/-352 | 提示配置可选 Cookie |
| `BILI_NOT_FOUND` | 账号或直播间不存在 | 显示未找到 |
| `LLM_NOT_CONFIGURED` | 未配置日程模型 | 跳过动态文字/图片分析；预约卡片仍可处理 |
| `LLM_AUTH_FAILED` | 模型凭证无效 | 阻止重试，提示检查密钥 |
| `LLM_BAD_OUTPUT` | 模型输出非预期 JSON | 丢弃该次结果并记录错误摘要 |
| `REMOTE_UNAUTHORIZED` | 远程 Token 错误 | 回到连接设置，不显示数据 |
| `REMOTE_OFFLINE` | WebSocket 或 HTTP 不可达 | 显示离线并可重连 |
| `VALIDATION_ERROR` | 非法时间、空标题、非法 URL | 返回 400，不写入数据库 |
| `SYNC_CONFLICT` | 离线修改与服务端当前值冲突 | 展示冲突摘要并等待用户选择 |
| `SYNC_QUEUE_BLOCKED` | 同步队列含无效记录 | 停止该记录同步，其余继续 |

## 9. 验收口径

- 账号搜索、订阅、官号关联不少于 1 条真实 B 站接口验证。
- 日程解析不少于 8 个正例和 6 个反例。
- 图片共享分析至少覆盖“同一图片关联两个主播”场景，模型调用计数必须为 1。
- WebSocket 覆盖连接、推送、断开、重连、鉴权失败。
- Windows 通知覆盖 false → true 单次通知与点击跳转。
- 本地和服务器两种模式均通过真实 GUI 操作验证。










## 10. 补充验收口径（2026-10-26 第二轮澄清）

- 连续 7 天窗口向前/向后移动 1 天，跨月和跨年正确。
- 日历网格与时间线切换后数据一致。
- 关闭窗口后进程驻留托盘，自启开关可持久化。
- 官号不产生开播通知。
- 关闭日程订阅后未来自动日程隐藏，重新开启后恢复。
- 删除自动日程后同来源不恢复，新来源可恢复。
- 预约取消后未来视图隐藏且历史保留。
- 手动编辑后自动刷新不覆盖。
- 服务器导入客户端不修改服务器，冲突选择三种策略均验证。
- 离线新增、修改、删除恢复后同步，重复同步不重复写入。
