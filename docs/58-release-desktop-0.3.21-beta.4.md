# OshiCal Desktop 0.3.21-beta.4 发布说明

本版相对 `0.3.21-beta.3`，改进正式版/测试版切换流程：用户主动从测试版切回正式版后，客户端会立即获取最新正式版并询问是否安装，不再要求用户额外点击一次“检查更新”。

## 本版变化

### 切回正式版时立即检查

- 在“设置 → 软件更新”中从测试版切换到正式版后，客户端会立即读取正式版清单并显示检查结果。
- 如果最新正式版可安装，客户端会弹窗询问是否立即更新；取消后仍可在更新卡片中稍后安装。
- 当正式版低于当前测试版时，弹窗会明确说明这一步是显式降级，只有用户确认后才会下载并安装。
- 自动检查仍只接受更高版本；后台流程不会把测试版静默降级为较低正式版。
- 测试版渠道继续同时比较测试版与正式版清单，并优先选择更高的 SemVer 版本。

## 数据、配置与兼容性

- 不改变数据库结构、API、环境变量或默认设置，无需迁移数据。
- 桌面端可显式降级到最新的正式版；该路径只由“从测试版切回正式版”的手动操作触发。
- 更新包继续使用 Tauri 签名校验，并要求发布清单中的版本与安装包签名版本一致。
- 使用服务端模式时，桌面端只负责切换本机软件版本，不会连带修改服务器版本或数据。

## 下载与安装

- 本次为测试版渠道：`0.3.21-beta.4`，Release 标签为 `desktop-v0.3.21-beta.4`。
- 普通用户请下载 NSIS 安装包 `OshiCal_0.3.21-beta.4_x64-setup.exe`。
- 已安装测试版的用户可在“设置 → 软件更新”中选择测试版渠道并检查更新。
- 从测试版切回正式版时，客户端会立即检查最新正式版并询问是否安装；是否降级由用户自行确认。
- 更新包使用 Tauri 签名校验；当前发布流程未启用 Windows Authenticode 代码签名，因此 Windows 可能显示未知发布者提示。
- 本次测试版发布不会移动桌面端正式版 `latest` 清单。

## 升级前操作与回滚

- 使用本地数据模式时，建议先备份 `%APPDATA%\com.oshical.desktop\oshical.db` 及相关 `-wal`、`-shm` 文件。
- 使用服务端模式时，桌面端本身不保存主日程数据；升级服务端前请另行备份服务端数据库和配置。
- 如需回滚，可在设置页切回正式版并按提示安装，或手动下载上一版本安装包。
- 自动更新和定时检查不会触发降级；回滚必须由用户主动切换渠道并确认。

## 已知限制

- 正式版与测试版之间的版本方向取决于当前两个清单；切换渠道不会删除本地数据。
- 安装包下载、签名校验与 Windows 实际覆盖安装由 GitHub Actions 发布流程验证。
