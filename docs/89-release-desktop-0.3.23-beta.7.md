# 推历 OshiCal 桌面端 0.3.23-beta.7 测试版

本版相对 `0.3.23-beta.6` 增加桌面端单实例保护。开机自启、快捷方式或开始菜单再次启动应用时，只会唤醒当前已经运行的 OshiCal，不再启动第二个进程和第二个系统托盘图标。

## 修复与体验变化

- 同一用户会话内只允许运行一个桌面端实例。
- 应用已在托盘或后台运行时再次启动，会显示、恢复并聚焦现有主窗口。
- 第二次启动会在进入其余插件和应用初始化前退出，不再重复打开数据库、启动监控任务或创建托盘图标。
- 开机自启保持不变；开启自启后再次手动启动程序也不会产生重复托盘。
- 如果升级前已经存在多个旧进程，系统可能暂时保留旧图标的显示状态；请先将所有旧版 OshiCal 进程完全退出，再启动本版一次。

## 数据、配置与兼容性

- 无数据库迁移、同步 schema、API 字段、环境变量或默认设置变更。
- 不修改服务器连接、凭据、直播采集、通知和开机自启配置。
- 本版只影响桌面端；服务端无需同步升级，仍按现有 `stable` / `beta` 渠道更新。
- 单实例范围是当前 Windows 用户会话；同一台电脑的不同 Windows 用户会话仍可各自运行一个实例。

## 下载、安装与渠道

- 版本与标签：`0.3.23-beta.7` / `desktop-v0.3.23-beta.7`。
- 普通用户下载 Windows x64 **NSIS 安装包** `OshiCal_0.3.23-beta.7_x64-setup.exe`。
- 已安装用户可在“设置 → 软件更新”中选择测试版并检查更新；本版会更新固定 `desktop-beta` 清单，不移动正式版更新清单，也不会自动降级。
- 更新包使用 Tauri 签名校验。当前发布工作流没有配置 Windows Authenticode 代码签名，Windows 可能显示“未知发布者”，这与 Tauri 更新签名不是同一套机制。

## 升级前操作、已知限制与回退

- 升级前退出客户端并备份完整数据目录、服务器连接配置和凭据。
- 如果当前系统已经出现两个托盘图标，请在任务管理器中确认旧版 OshiCal 进程后全部退出，再安装并只启动本版一次。
- 本版未在本机执行构建或测试；构建、测试、签名和产物验证由本次 GitHub Actions Release 工作流执行，结果以该工作流为准。
- 需要真实验收“开机自启后再次手动启动”“托盘隐藏后再次启动”和“关闭窗口后再次启动”三个场景，确认始终只有一个托盘图标且已有窗口被唤醒。
- 需要回退时安装此前保留的 `0.3.23-beta.6` 桌面测试版并恢复必要的本地数据备份；旧版不包含单实例保护，回退后应避免在已运行一个实例时再次启动程序。
- 本版只发布 beta；正式版须待测试反馈确认后另行批准。发布时将本文原文写入对应 GitHub Release 正文。
