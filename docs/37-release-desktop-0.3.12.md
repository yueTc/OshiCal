# 桌面端 0.3.12 发布说明

## 这一版改了什么

和 [服务端 0.3.20](36-release-server-0.3.20.md) 同源：桌面端和服务器共用 `crates/core` 里的同一套分析管线，所以单次调用、思考程度、账号池这三件事在桌面端同时生效。

## 桌面端要点

- **一条动态只调用一次模型**：本地抓到的动态同样把正文 + 全部图片合成一个请求，9 图动态不再发 10 次。
- **思考程度可选**：设置 → 日程识别模型 → 思考程度（自动 / 低 / 中 / 高），默认自动，不发送 `reasoning_effort`。
- **并行个数**：1~8，实际并行度 = min(设置值, 账号数)；同一账号内部始终串行。
- **账号列表**：可添加多个模型账号，每个账号独立的 Base URL、模型和密钥；密钥只显示「已配置 / 未配置」，不回显明文。
- 桌面端没有服务端的多账号密钥下发通道，密钥保存在本机 secrets 存储里，按 `account_id` 分开。

## 升级后会发生什么

- 本地库会新增 `post_analyses` 表，旧的 `text_analyses` / `image_analyses` 保留只读，不再写入。
- `prompt_version` 升到 `*-post-v1`，历史动态会重新分析一遍。第一次刷新明显变慢，属于预期。
- 纯文字动态的日程来源标识不变，历史日程不会重复；带图动态的标识带上了内容摘要，换图后会重新建条并清理旧来源。

## 构建

本版本只改源码，安装包由 CI 产出：

- `desktop-v0.3.12` tag 触发 Windows 构建，产物 `OshiCal_0.3.12_x64-setup.exe` + `.sig` + `latest.json`。
- 应用内更新读取 `latest.json`，所以必须先发布 Release 再推更新提示。
