# OshiCal Desktop 0.3.21 发布说明

本版是 `0.3.21` 正式版，汇总相对 `0.3.20` 的测试周期更新。桌面端与服务端共用 `crates/core`，同槽重复日程合并修复同时进入服务端 `0.3.29`。

## 本版变化

### 日程与更新体验

- 新增同槽重复日程合并：同一主播、同一开始时间、同一直播间的预约卡、图文和文字识别结果会合并为一张卡片，单人场次也参与去重。
- 合并时优先保留预约卡官方标题，同时保留结束时间和全部自动来源，后续取消、改期与来源追踪仍可继续工作。
- 测试版渠道会同时比较测试版与正式版清单，并选择更高的 SemVer 版本。
- 从测试版主动切回正式版后会立即检查最新正式版并询问是否更新；若目标正式版更低，会明确提示这是用户确认后才执行的显式降级。

### 日程页

- “直播日程”标题、操作按钮和日期导航条组成吸顶区域，滚动时持续可见。
- 吸顶区域只在贴住窗口顶部后显示背景遮罩，并在下方保留内容间隔。
- “新增日程”等主题色主按钮的文字和图标固定为白色，保证不同配色下的对比度。

### 主播库

- 删除标题下方的说明文字，精简顶部信息。
- 修复月相、粉丝数和操作区挤压订阅开关的问题；订阅开关使用完整内容宽度并保持单行。
- 主播姓名、UID、月相和操作按钮的垂直对齐已调整，长姓名省略显示。

### 设置页

- 设置标题与“保存设置”按钮组成吸顶区域，并统一左上角标题样式。
- 删除多处重复或冗长说明，覆盖运行模式、同步、服务器更新、采集参数、网络代理、直播统计、界面配色、提醒与运行、软件更新和日程模型。
- B 站登录卡片增加“服务端已登录 / 服务端未登录”状态胶囊。
- 更新渠道切换到卡片右上角并改为胶囊样式；服务端与客户端保持一致。
- 渠道切换提示和“设置已保存”提示在 3 秒后自动消失。
- 自定义配色区域只在选中“自定义配色”后出现。
- 直播数据统计开关改为文字位于开关前；自动分析开关移动到日程识别模型卡片右上角。
- 思考程度改为下拉选择，“关闭”对应原先的“自动”行为。

## 数据、配置与兼容性

- 不改变数据库结构、API、环境变量或默认配置，无需数据迁移。
- 更新渠道、清单签名、镜像摘要和自动更新规则保持兼容。
- 自动检查不会把测试版静默降级；显式降级只由用户主动切回正式版并二次确认触发。
- 本次 UI 调整同时影响桌面客户端与服务端 Web 管理界面的设置页。

## 下载与安装

- 正式版渠道：`0.3.21`，Release 标签为 `desktop-v0.3.21`。
- 普通用户请下载 NSIS 安装包 `OshiCal_0.3.21_x64-setup.exe`。
- 已安装用户可在“设置 → 软件更新”中选择正式版渠道并检查更新。
- 更新包使用 Tauri 签名校验；当前发布流程未启用 Windows Authenticode 代码签名，因此 Windows 可能显示未知发布者提示。
- 本次正式版会更新桌面端 `desktop-v*` 正式 latest 清单，不会移动测试版清单。

## 升级前操作与回滚

- 使用本地数据模式时，建议先备份 `%APPDATA%\com.oshical.desktop\oshical.db` 及相关 `-wal`、`-shm` 文件。
- 使用服务端模式时，桌面端本身不保存主日程数据；升级服务端前请另行备份服务端数据库和配置。
- 如需回滚，可手动安装上一份桌面安装包；自动更新不会主动降级到较低版本。

## 已知限制

- 无法证明属于同一场的不同直播间记录仍会保留，避免误删真正并行的场次。
- 已存在的重复日程需要等待一次完整刷新，或在客户端手动刷新受影响主播后才会合并。
- 安装包、签名、自动更新和真实覆盖安装由 GitHub Actions 发布流程验证。
