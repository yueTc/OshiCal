# 推历 OshiCal 桌面端 0.3.23-beta.6 测试版

本版相对 `0.3.23-beta.5` 修复客户端连接已经配置好 API Key 的服务端时，被本地模型地址覆盖而出现“当前 API Key 未绑定到目标模型地址”的问题；同时改进连接测试和 Windows 安装器语言设置。服务端 API、同步协议和数据库结构没有新增变更。

## 修复与体验变化

- 首次连接或切换服务端时，客户端先读取并采用服务端已有的采集、模型和开关配置，不再把本地草稿中的默认模型地址写回服务端。
- 已有服务端即使保存的是早期未显式绑定 URL 的 API Key，也可以先完成连接；模型地址等配置会保留原值，连接成功后再进行设置修改。
- “测试连接”不再只访问公开的健康检查，而是同时验证需要鉴权的接口；访问令牌错误时会直接显示未授权，不会误报为已连接。
- NSIS 安装器固定使用简体中文并隐藏语言选择器，避免安装时出现不合适的界面语言。
- 共享核心的图片准备流程限制同时处理的图片数量，降低桌面本地分析多张高清原图时的内存峰值。该改动原先随服务端 `0.3.31-beta.4` 发布；桌面端本次一并包含。模型请求格式、日程识别和缓存语义不变。

## 数据、配置与兼容性

- 无数据库迁移、同步 schema、API 字段或环境变量变更。
- 本次没有修改服务端程序；服务端可继续使用当前已部署的测试版。客户端和服务端仍按现有 `stable` / `beta` 渠道更新。
- 首次连接已有服务端不会再改写模型地址；如用户主动更换模型地址，仍需为新地址重新保存对应的 API Key。
- 图片准备并发从“最多四张”调整为“最多两张”，大量高清图片场景可能略微降低准备吞吐，但单次分析仍会完整执行。

## 下载、安装与渠道

- 版本与标签：`0.3.23-beta.6` / `desktop-v0.3.23-beta.6`。
- 普通用户下载 Windows x64 **NSIS 安装包** `OshiCal_0.3.23-beta.6_x64-setup.exe`。
- 已安装用户可在“设置 → 软件更新”切换或检查测试版渠道；本版会更新固定 `desktop-beta` 清单，不移动正式版更新清单，也不会执行自动降级。
- 更新包使用 Tauri 签名校验。当前发布工作流没有配置 Windows Authenticode 代码签名，Windows 可能显示“未知发布者”，这与 Tauri 更新签名不是同一套机制。

## 升级前操作、已知限制与回退

- 升级前退出客户端并备份完整数据目录、服务器连接配置和凭据；连接服务端时同时按现有规范备份服务端数据库、主密钥和配置。
- 本版未在本机执行构建或测试，构建、测试、签名和产物验证由本次 GitHub Actions Release 工作流执行，结果以该工作流为准。
- 若连接异常，重新确认服务地址和访问令牌，并查看“测试连接”是否通过；仍失败时保留应用日志和错误提示，不要直接把 Token 或 API Key 写入日志或公开 Issue。
- 需要回退时安装此前保留的桌面测试版并恢复必要的本地数据备份；回退程序不会自动恢复服务端数据库或已修改的服务器设置。
- 本版只发布 beta；正式版须待测试反馈确认后另行批准。发布时将本文原文写入对应 GitHub Release 正文。
