# OshiCal 0.3.0

客户端与服务端统一发布 0.3.0，继续使用独立发布标签 desktop-v0.3.0 和 server-v0.3.0。

- 修复同步 ACK 持久化、缓存恢复、监控切换与重建时的竞态。
- 修复设置、日程和主播管理的异步保存及重复提交问题。
- 修复数据导入的 revision、固定周表关联和迁移冲突处理。
- 修复文字/图片分析失败被后续无关刷新清除的问题。
- 加固模型请求目标校验、密钥与 URL 绑定、代理凭据脱敏及响应大小限制。
- 改进直播采集器停止、认证、超时、重连和匿名礼物统计，保留 v2 直播状态通知。
- 加固宿主更新代理的路径、签名、备份、并发和回滚处理。

## 服务器宿主更新代理升级

0.3.0 的宿主更新代理要求 HMAC-SHA256 签名。发布 workflow 使用仓库 Secret
OSHICAL_SERVER_UPDATE_HMAC_KEY（64 位小写十六进制字符串）。宿主机必须将相同密钥
保存到 /etc/oshical/updater-hmac.key，所有者 root，权限 0400 或 0600，并安装本版本
scripts/oshical-updater-agent.sh、scripts/update-server.sh 和 systemd unit 后重新加载。
密钥不能写入仓库或容器可写目录。未配置时宿主更新代理拒绝更新；手动 Docker 部署不受影响。

旧安装在升级镜像后仍需单独更新宿主脚本和 unit。旧代理不验证签名，不能依靠镜像升级替代宿主升级。

## 验证

本机只进行源码格式化、语法和差异检查，不构建、不编译、不运行测试。
实际 Rust/前端检查、测试以及 Windows 安装包和服务器镜像构建由 GitHub Actions 执行。
