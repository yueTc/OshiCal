# 推历 OshiCal 服务端 0.3.31-beta.2 测试版

本版相对 `0.3.31-beta.1`，调整直播间去重和开播卡绑定，并补全 B 站转发动态的原作者上下文。变更位于共享核心，也影响桌面本地采集；连接服务端的客户端建议配套升级至 `0.3.23-beta.4`。

## 新增、修复与体验变化

- 同一直播间、开始时间相差不超过 10 分钟的自动日程优先按直播间合并，不再依赖参与者名称重合，覆盖空参与者开播卡和跨账号团播预告。
- 已明确属于不同直播间的记录不因参与者重合而合并；保留不同时间段及已分别绑定两个独立直播场次的记录，保护人工锁定记录。
- 开播状态可绑定其他账号发布、但指向当前直播间的日程；迟到的预告也可附加至该房间已有开播卡，避免按发布账号重复建卡。
- 删除自动重复卡前迁移开播状态与统计场次引用，并保留来源；快照导入校验接受有明确直播间证据的跨账号绑定。
- 转发动态分析附带原作者昵称、MID、动态编号、链接、发布时间、正文、预约信息及可读取图片，区分原作者与转发者，避免仅凭转发关系推断参与者或房间。

## 数据、配置与升级前操作

- 无新增数据库迁移、环境变量或 API 字段，同步 schema 不变；原有 YouTube 总开关、OAuth、凭据及更新代理配置保持不变。
- 分析缓存版本更新为 post-v5，下次刷新可能重新调用模型分析历史动态；请留意模型费用和刷新耗时。
- 升级前停止服务，备份数据库及必要的 WAL/SHM、凭据主密钥文件、环境变量和更新代理配置；保留旧镜像或二进制。
- 升级后正常采集刷新会处理已有重复记录。去重会合并来源并删除自动重复卡；恢复合并前记录需要数据库备份，单独回退二进制或镜像不会拆回记录。

## 适用产物与渠道

- 版本与标签：`0.3.31-beta.2` / `server-v0.3.31-beta.2`。计划适用 GitHub Actions 生成的 Linux x86_64、Windows x86_64 服务端二进制及 `ghcr.io/yuetc/oshical-server:0.3.31-beta.2` 镜像，实际可用产物以通过验证的 Release 附件为准。
- Release 必须标记为 prerelease，只维护固定 `server-beta` 清单；不得移动 `server-latest`、Docker `latest` 或正式版通道。
- 构建、测试、镜像生成、产物验证与发布一律通过 GitHub Actions 或用户明确指定的外部构建机。

## 已知限制与验证状态

- 转发原文不可用时只分析可读取的附言；嵌套转发最多四层，模型仍最多分析每条动态前两张图片。
- 共享核心已补充房间去重、跨账号绑定、统计引用迁移、快照导入和转发上下文回归用例；本机仅作静态检查，尚未运行 CI、真实采集或升级产物验证。
- 本文件是发布正文草稿，发布前需按 CI 和实际产物结果定稿并写入同版本 GitHub Release 正文。beta 验证后需另行询问是否发布正式版。
