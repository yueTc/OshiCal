# 服务端 0.3.30-beta.5（测试版）

本版相对 0.3.30-beta.4，优化同步历史占用，并增加直播人数时间序列的服务端存储与查询能力。

## 变化

- 同步历史清理改为每 1 小时检查；启动后约 60 秒进行首轮。保留上限为 7 天、最新 10,000 条、20 MiB JSON 内容，任一限制达到便按连续旧前缀分批清理。检查间隔内允许暂时超限，容量不包含索引、SQLite 页开销、WAL 和备份。
- 自动识别得到相同日程、相同来源，或直播累计统计没有变化时，不再重复生成相同业务快照。实际内容、删除和状态变化仍正常同步；最后刷新时间继续更新，不隐瞒刷新状态。
- 新增直播人数时间序列：约每 30 秒保存该采样窗口内最新公开高能用户数及原始观测时间，同时继续保留全场峰值。高能用户数不等于全体观众真实同接。
- 人数下降和真实零值分别保留；未收到新观测、断线和停止时无有效观测则记录缺失（null），不会把峰值当作当前人数或把缺失补成零。不是每个上游事件都存档，也不保存弹幕正文。
- 采样存于独立表，不在每次同步快照中重复附带整条历史。

## 数据与 API

- 启动时自动新增 live_online_samples 表及索引，旧场次不回填不存在的历史观测。采样随所属场次保留，删除所属主播会级联删除，不受同步历史保留窗口影响。
- 新增需鉴权的 GET /api/live-sessions/{id}/online-samples?afterId=0&limit=500；返回 metric=bilibili_high_energy_users、sampleIntervalSeconds=30、samples、nextAfterId 和 hasMore，limit 为 1–1000。
- 现有同步协议 v2 和场次汇总接口保持兼容。曲线按需查询；现有桌面安装包和界面不新增曲线，也不会离线同步这张采样表。需要离线曲线或图形展示需后续客户端支持。
- 本版无新增环境变量。离线客户端需要的旧日志若已过期，将按现有 resetRequired 机制重新全量同步；7 天不是保证可补增量的时长，数量或容量限制可能更早触发。

## 升级与回滚

适用于服务端 0.3.30-beta.5 的 CI Linux/Windows 编译产物及同版本服务端镜像，属于 beta 渠道，不移动 server-latest 或 Docker latest 正式渠道。

升级前备份完整 SQLite 数据（使用一致性备份，或停服后连同必要 WAL 一并备份）与配置；保留旧镜像及更新代理配置。已有模型、代理和凭据设置不变。新采样仅从升级并启用直播统计后开始产生；未采集和停服期间不补造观测。

清理仅释放数据库内部页面，不保证数据库文件立即缩小。本版不自动运行 VACUUM；若需回收磁盘文件，应在完整备份后另行安排维护窗口。回滚旧程序不具备新采样查询能力，恢复升级前数据库会丢失备份之后的所有新数据，应先保留当前完整备份。
