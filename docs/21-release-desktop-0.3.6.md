# OshiCal Desktop 0.3.6

本次仅发布桌面端，标签为 `desktop-v0.3.6`。服务端保持 `0.3.10`，不再重复发布。

## 日程卡片：右键直接进入直播间

之前只有整张卡片单击才会打开直播间，右键菜单里没有对应入口，用户想在打开菜单的同时进房间得先关掉菜单再点卡片。

- 右键菜单、移动端长按菜单、卡片右上角「⋯」菜单共用同一份菜单，首项新增「进入直播间」（`MonitorPlay` 图标）。
- 目标地址按 **日程直播间地址 → 主播直播间地址 → 主播房间号（`https://live.bilibili.com/{roomId}`）** 解析，和主播库右键的「进入直播间」同一套规则；菜单项的 `title` 直接显示即将打开的地址，点之前就能确认。
- 直播中的日程，该项使用直播色（`--live`）加重显示，一眼能区分“现在真在播”的卡片。
- 三处入口一致：整卡点击（含 Enter/Space）过去只认 `schedule.roomUrl`，没有配置时会提示“没有配置直播间地址”；现在与右键菜单走同一个解析函数，不会再出现“右键能进、点卡片说没地址”的割裂。
- 三者都解析不到地址时提示「该日程还没有直播间地址，可在右键菜单里选择“编辑”补充」。

## 时间线卡片「⋯」不再越出卡片

- 原因：`.card-more` 是卡片网格第 4 列的网格项，而 `.icon-button` 是 35×35，第 4 列只有 26px（每行 1–2 场）／24px（每行 3–4 场），按钮以 start 对齐向右溢出。实测每行 4 场时真实溢出 1px，其余情况只剩 4px 间距、视觉上贴住圆角边框。
- 改法：`.card-more` 改为卡片内绝对定位（`top: 9px; right: 12px`，28×28，圆角 8px），第 4 列继续保留作为让位空间，标题与徽标不会被按钮压住；移动端断点同步为 `right: 8px; top: 8px`；日历视图原有的 22×22 覆盖规则不变。
- 实测（真实 `styles.css` + `getBoundingClientRect`）：每行 2 场与 4 场下按钮距卡片右边缘均为 13px，旧实现分别为 4px 与溢出 1px；三个点整体左移约 4px。

## 随包携带的抓取改进

桌面端内置核心库（本地模式与本地抓取）同步了 0.3.10 服务端的解析改动：

- 带直播预约的动态以预约卡片那一场为准，正文里与预约时间相同（±10 分钟）的条目丢弃、不重复入库；正文另写的时间点仍单独入库。
- 正文是否还有“另一场”由逐行时间解析判定，预约动态里的 `cancel` 不采信。
- 正文识别不再依赖“时间在前、事项在后”的语序，忽略行首 `*`、`·`、`-`、`👉` 等项目符号。
- GIF/动图不进入视觉模型，跳过不计为失败，也不占模型调用额度。

## 兼容性

- 数据模型、IPC 命令和 HTTP 接口均未变化；0.3.5 的本地数据库可直接升级，无需迁移。
- 更新清单（`latest.json`）由 `release.yml` 生成，Windows 更新优先使用 NSIS 安装包。
- 未做 Authenticode 代码签名，Windows SmartScreen 可能提示；更新包仍使用 Tauri 签名校验。
