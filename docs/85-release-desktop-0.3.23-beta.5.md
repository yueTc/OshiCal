# 推历 OshiCal 桌面端 0.3.23-beta.5 测试版

本版相对 `0.3.23-beta.4` 修正动态日程的参与者归属。改动位于共享核心，也影响服务端采集；连接服务端的用户需要服务端配套更新至 `0.3.31-beta.3` 才能使用新的服务端识别规则。

## 修复与体验变化

- 删除“单人日程匹配不到主播就归给动态发布者”的兜底，避免纯转发、应援他人的个人直播被收录到转发者日程。
- 单人场优先按明确参与者归属，不再让冲突的 performer 或 aliases 覆盖参与者。发布者确实参加的多人联动仍可收录，直播间允许属于其他账号。
- 已有模型缓存读取后同样经过归属校验；未改变提示词缓存版本，不强制全量重新调用模型。

- 被拒绝的不相关模型结果不再占用预约时段，保留正常预约卡的标题、时间和归属，避免过滤误收时连带漏掉真实预约。

## 数据、配置与兼容性

- 无数据库迁移、环境变量、API 或同步 schema 变更。
- 身份无法匹配时不再猜测归属，可能跳过昵称或别名未配置完整的真实日程；可核对别名或手工补录。
- 本版不按“直播间属于他人”批量删除历史卡片，避免误删真实联动；已经误收的记录需核对来源后手动删除。

## 下载、安装与渠道

- 版本与标签：`0.3.23-beta.5` / `desktop-v0.3.23-beta.5`；发布时标记 prerelease，只维护 `desktop-beta`，不移动正式渠道。
- 普通用户下载 Windows x64 **NSIS 安装包**；已安装用户可在“设置 → 软件更新”检查更新，选择 beta 渠道。
- 自动更新包使用 Tauri 签名校验。当前发布工作流未配置 Windows Authenticode 代码签名步骤，Windows 仍可能显示“未知发布者”。

## 升级前操作、验证与回退

- 升级前退出客户端并备份完整数据目录、连接配置与凭据主密钥；连接服务端时同时备份服务端数据。
- 发布前 GitHub Actions CI 已通过：前端类型检查、Rust 格式与 lint、前端测试、492 项 Rust 测试、前端生产构建及 17 组真实浏览器交互；7 项需要真实网络或平台环境的测试保持忽略。回归覆盖纯转发不落库、参与者冲突、真实联动、缓存复用及预约卡兜底。CI 记录：`43598398392`；未宣称已验证真实 B 站采集、Windows 安装交互或生产环境升级。
- 如需回退，使用之前保留的安装包并恢复必要备份；回退程序不会恢复手动删除的记录。
- 正式版须待 beta 验证后另行确认；产品发布时将本文原文写入对应 GitHub Release 正文。
