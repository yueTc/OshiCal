# 推历 OshiCal 服务端 0.4.0 正式版

本版相对上一服务端正式版 `0.3.30`，汇总 `0.3.31` 测试周期并进入 `0.4.0` 正式版：新增 YouTube 平台服务、OAuth 与凭据保管、社区和直播数据、聊天与 Super Chat 统计，并同步共享核心的直播间去重、参与者归属、预约兜底和图片内存控制改进。建议桌面客户端同步升级到 `0.4.0`。

## 新增功能与体验变化

### YouTube 服务
- 新增 YouTube 搜索、订阅、官号关联、状态、API Key、OAuth、网页会话和直播刷新接口，所有功能受 `youtube_enabled` 总开关控制，默认关闭。
- 支持公开社区帖和会员社区帖解析、预约直播、开播/下播、最近直播、场次统计、Super Chat / Super Sticker、会员事件及聊天消息统计。
- 新增 YouTube OAuth 启动、完成、刷新与退出流程；API Key 和会话凭据加密保存，不以环境变量作为主配置路径。
- 修复关联账号删除事件丢失平台、OAuth 刷新/退出竞态、社区帖来源指纹漂移、会员预览图片泄露和聊天重启后重复计数；聊天消息使用场次级持久 ID 去重。

### 日程与共享核心
- 同一直播间、开始时间相差不超过 10 分钟的自动日程优先按直播间合并，不同直播间不会因参与者重合被错误合并。
- 修正单人日程的参与者归属；转发动态保留原作者上下文，不把转发者自动视为主播或直播间主人。
- 被拒绝的不相关模型结果不再占用预约时段，正常预约卡可保留。
- 图片准备流程限制同时处理的图片数量，降低高清原图并发分析时的内存峰值。
- 同步快照、导入导出、删除事件和直播间绑定继续保护人工锁定与来源信息。

## 数据迁移、API 与环境变量

- 同步实时协议升级为 **schema 3**；旧桌面客户端不能安全解析新同步数据，必须升级到 `0.4.0`。
- 新增 `live_super_chat_events`、`live_youtube_chat_events` 及相关索引；旧列集或中间测试版列集检测到缺口时，迁移前使用 `VACUUM INTO` 生成一致性备份。
- 新增 `OSHICAL_YOUTUBE_CLIENT_ID`、`OSHICAL_YOUTUBE_CLIENT_SECRET`；可选 `OSHICAL_YOUTUBE_OAUTH_REDIRECT_URI`。非回环回调地址必须使用 HTTPS，`localhost`、`127.0.0.1` 和 `[::1]` 才允许 HTTP。
- 未显式配置 `OSHICAL_SECRETS_KEY` 时，首次启动会生成随机主密钥文件，默认位于数据库同目录，也可用 `OSHICAL_SECRETS_KEY_FILE` 指定数据库外路径。
- 原有 Token、模型、代理、数据库路径和宿主机更新代理配置继续保留；YouTube 功能默认关闭，不会自动发起平台请求。
- 旧桌面同步 schema 2 客户端必须拒绝连接或提示升级，不能把 schema 3 数据交给旧客户端解析。

## 正式产物与更新渠道

- 正式版本：`0.4.0`；正式标签：`server-v0.4.0`。
- GitHub Actions 正式产物包括 Linux x86_64 `oshical-server-0.4.0-linux-x86_64.tar.gz`、Windows x86_64 `oshical-server-0.4.0-windows-x86_64.zip` 及各自的 SHA-256 校验文件。
- 固定镜像：`ghcr.io/yuetc/oshical-server:0.4.0`；正式浮动镜像：`ghcr.io/yuetc/oshical-server:latest`。实际更新以签名清单中的不可变镜像摘要为准。
- 正式版发布更新 `server-latest` 清单和 Docker `latest`，同时保留 `server-beta` 与测试镜像；客户端测试版不会因本次发布被自动降级。
- 服务端更新清单使用现有 HMAC 签名；宿主机更新代理继续校验镜像仓库、版本和摘要，不要绕过验签。

## 升级前操作、已知限制与回退

- 升级前停止服务，备份完整 SQLite 数据库及必要的 WAL/SHM、主密钥文件、`.env`、OAuth 配置、反向代理和更新代理配置，并保留旧镜像或编译产物。
- 主密钥文件与数据库必须成套备份。丢失主密钥且没有外部 `OSHICAL_SECRETS_KEY` 时，已加密的 YouTube 凭据无法恢复；回滚前也必须保留新主密钥文件。
- 社区页当前只解析首屏，不抓取 continuation 多页；预约直播只检查最近 20 个上传；频繁搜索可能消耗用户自己的 API 配额。
- 聊天 continuation token 不跨进程持久化，持久消息 ID 只用于避免重复累计；聊天事件表暂无独立清理策略，长期使用会增加数据库体积。
- 旧场次和停服期间不补造直播采样；直播人数表示公开高能用户数，不等同于全体观众真实同接。
- 如需回退，先备份升级后的完整数据库与主密钥，再固定旧镜像或旧编译包；必要时恢复升级前备份。恢复旧备份会丢失备份之后的记录，旧版本也不提供本版 YouTube 与 schema 3 能力。
- GitHub Actions 发布镜像、编译产物和更新清单不等同于已经替自托管主机完成部署；升级后请核对健康状态、数据库迁移、Token、订阅/日程数量及一场真实直播的关联结果。
