# OshiCal Desktop 0.3.21-beta.3 发布说明

本版相对 `0.3.21-beta.1`，新增同槽重复日程合并修复，并保留正式版/测试版更新渠道。桌面端与服务端共用 `crates/core`，相同修复已经进入服务端 `0.3.29-beta.2`。

## 本版变化

### 重复日程修复

- 同一主播、同一开始时间、同一直播间的预约卡、图文和文字识别结果会合并为一张日程卡片，不再并排显示多条近似记录。
- 单人场次现在也参与自动去重，不再只处理多人团播。
- 预约卡与图文识别标题措辞不同时，优先保留预约卡官方标题，同时保留后续识别出的结束时间与来源。
- 合并日程时会把重复项的全部来源迁移到保留日程，后续取消、改期、来源追踪和同步事件不会因合并丢失。
- 下一次刷新后，历史遗留的同槽重复日程会自动合并，不需要用户手工删除。

### 更新渠道

- 设置页“软件更新”提供 `stable`（正式版）与 `beta`（测试版）两个渠道。
- 测试版渠道同时检查测试版和正式版清单，并按 SemVer 选择更高版本；同一核心版本发布正式版后，测试版客户端可以升级回正式版。
- 测试版使用独立的 `desktop-beta/latest-beta.json` 清单，不会占用桌面端正式版 `latest` 通道。

## 数据、配置与兼容性

- 不改变数据库结构、API、环境变量或默认设置，无需迁移。
- 手动锁定的日程不会被本次自动合并删除。
- 如果升级后尚未刷新，已有重复可能暂时保留；等待后台刷新或在“日程”页手动刷新受影响主播即可。
- 更新器只接受更高版本，不会自动降级；测试版核心版本高于当前正式版时，切回正式版仍需等待更高的正式版。

## 下载与安装

- 本次为测试版渠道：`0.3.21-beta.3`，Release 标签为 `desktop-v0.3.21-beta.3`。
- 普通用户请下载 NSIS 安装包 `OshiCal_0.3.21-beta.3_x64-setup.exe`。
- 已安装测试版的用户可在“设置 → 软件更新”中选择测试版渠道后检查更新；仍停留在正式版且设置页没有渠道选项的用户，请下载 NSIS 安装包完成升级。
- 更新包使用 Tauri 签名校验；当前发布流程未启用 Windows Authenticode 代码签名，因此 Windows 可能显示未知发布者提示。
- 测试版发布不会移动正式版 `latest` 清单。

## 升级前操作与回滚

- 使用本地数据模式时，建议先备份 `%APPDATA%\com.oshical.desktop\oshical.db` 及相关 `-wal`、`-shm` 文件。
- 使用服务端模式时，桌面端本身不保存主日程数据；升级服务端前请另行备份服务端数据库和配置。
- 如需回滚，可手动安装上一测试版安装包；测试版与正式版之间不会自动降级。

## Beta.3 说明

- `0.3.21-beta.2` 的桌面发布工作流漏写版本输出，未生成桌面安装包或 Release；`beta.3` 是同一 PATCH 内的桌面发布修正版。
- 服务端 `0.3.29-beta.2` 已成功发布，并包含相同的同槽重复日程修复。

## 已知限制

- 无法证明属于同一场的不同直播间记录仍会保留，避免误删真正并行的场次。
- 本机验证已覆盖桌面端 Clippy 与单元测试；安装包、自动更新和真实 UI 刷新仍由 GitHub Actions 发布流程验证。
