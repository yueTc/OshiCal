# 推历 OshiCal 桌面客户端 0.3.22（正式版）

本版相对上一正式版 `0.3.21`，汇总本轮直播卡片、人数曲线、独立采集与同步维护、弹层和托盘改进。建议服务器模式同时升级服务端至 `0.3.30`，以使用完整的直播补卡与历史曲线能力。

## 新增与体验改进

### 托盘直播快捷入口
- 右键托盘可查看已添加且正在直播的主播头像、名字，点击后使用默认浏览器打开对应的 B 站直播间；原有打开主窗口、立即刷新和退出操作保留。
- 同时支持本地与服务器模式，始终读取当前来源。点击前重新核实来源，避免切换服务器后误开另一位同编号主播的房间。
- 最多 8 人直接列出，更多时收进“正在直播（人数）”子菜单，无人开播时显示提示。头像异步缓存，兼容内嵌 WebP/PNG/JPEG 及受信任的 B 站图片地址；修复内嵌头像被过滤而显示软件 Logo 的问题，图片加载中或损坏时留空。

### 直播日程与场次关联
- 没有预告的真实开播会生成一张“开播补录”日程卡，不再因为没有预告而在日历中缺席。是否补卡遵循主播的日程采集开关，不要求开启通知或统计。
- 实际开播前后 2 小时内的有效预告可复用；卡片与本场直播明确绑定，跨午夜、同日多条日程和标题变化不再误高亮其他预告。
- 同一直播间下播后 30 分钟内恢复（含边界）按续播处理，保留首次开播时间、日程卡和累计统计；请求失败不当作下播，删除或取消的本场卡片不会被轮询恢复。
- 服务器明确表示没有绑定卡片时，不再退回高亮另一张预告；连接缺少新字段的旧服务器时，仅保留前后 2 小时的兼容匹配。

### 人数变化曲线与弹层
- 在日程“查看直播数据”中点击“最高同时在线”可打开本场人数曲线，支持整场、最近 1 小时、最近 3 小时、悬停与拖动时间滑块；滑块可用方向键调整。
- 直播期间每 30 秒按需读取新增采样；关闭曲线后停止该视图的定时读取。人数下降和真实 0 保留，缺失或较长未采集区间断开显示，不插值、不补零；读取失败保留已有数据并允许重试。
- 直播数据、同接曲线、扫码登录和模型选择弹层移除重复的底部关闭按钮；统一保留右上角关闭与适用的遮罩关闭方式。同接曲线标题固定，内容独立滚动；保留数据迁移、保存设置等需要独立决策的主操作。

## 独立模式、数据与兼容性

- 共用 `crates/core` 的采集改进同时适用于本地客户端和配套服务端：按动态发布时的北京时间自然周理解无明确日期的周表，明确日期优先；有效历史日程保留原日期，不平移到当前周。只处理正常抓取范围，不自动补齐整站历史。
- 独立主播刷新按设置有界并行（1–8，默认 1），同一主播保持旧到新串行；共享来源去重，图文只选择前两张图片。相同准备范围的进行中刷新共享结果；识别失败采用 1/5/15/30 分钟退避，内容或识别配置变化可重新尝试。首次从旧正式版升级刷新可能重新分析并增加模型调用、耗时与计费。
- 本地同步历史在进入独立模式约 60 秒后首轮维护，之后每小时检查，按 7 天、最新 10,000 条或 20 MiB JSON 内容的先到限制分批清理；只清同步历史，不删业务日程或场次。不保证数据库文件立即缩小，也不自动执行 VACUUM。
- 启动时自动增量建立直播采样、轻量场次状态及卡片绑定字段。旧数据库无需手动建表，但升级前必须备份。原有模型、代理、凭据和更新渠道设置保留，无新增必填环境变量。
- 直播人数采样按约 30 秒窗口保留最新公开高能用户数及观测时间，**不是全体观众真实同接**。仅从程序运行并启用统计后开始采集，旧场次、停服和断线期间不补造数据。
- 本地曲线读本机，服务器曲线读当前服务器的鉴权接口；服务器离线时没有完整曲线离线缓存。JSON 快照不等于完整统计/采样数据库备份，备份请使用完整 SQLite 数据。

## 下载、更新与渠道

- 正式标签：`desktop-v0.3.22`。普通用户下载 Windows x64 **NSIS 安装包** `OshiCal_0.3.22_x64-setup.exe`。
- 已安装用户可在“设置 → 软件更新”选择正式版渠道并检查更新。测试版渠道继续同时读取测试版与正式版清单，按 SemVer 选择较高版本，本版正式版高于同核心版本的测试版；不会在后台自动降级。
- 自动更新包使用 **Tauri 签名校验**；当前发布流程未配置 Windows Authenticode 代码签名，系统仍可能提示“未知发布者”。请仅从本项目正式 Release 或客户端内更新。
- 编译、测试、签名和发布由 GitHub Actions 执行，不使用之前的本地未签名包作为在线更新产物；保留固定 `desktop-beta` 测试清单。

## 升级前操作、限制与回退

1. 备份客户端完整数据目录、服务器连接与配置。本地模式可停用客户端后备份 `%APPDATA%\com.oshical.desktop`，包含数据库及必要的 WAL；不要只复制运行中不断写入的 `oshical.db`。
2. 手动安装前退出旧客户端。服务器模式建议同步升级服务端 `0.3.30`；旧服务端不会因只升级客户端而新增自动补卡和采样接口。
3. 原生托盘已通过真实缓存头像的解码回归，但实际原生菜单显示、点击和覆盖安装尚未完成自动化现场验收，升级后请核对。托盘离线时使用缓存状态，不保证离线期间开播状态实时更新。
4. 30 分钟内主动下播再开也可能归入续播；超过预告前后 2 小时可能保留原预告并另建补录卡。旧错周记录不会保证自动清除，需在备份后按来源核对，手动锁定与删除抑制仍生效。
5. 如需回退，可手动安装上一正式版 `0.3.21`；先保存当前完整数据，必要时恢复升级前备份。恢复旧备份会丢失备份之后的记录，旧版本也不提供本版新增曲线、补卡或托盘能力；自动更新不会替用户执行降级。
