# OshiCal Server 0.3.29 发布说明

本版是 `0.3.29` 正式版，汇总相对 `0.3.28` 的测试周期更新。桌面端与服务端共用 `crates/core`，同槽重复日程合并修复同时进入桌面端 `0.3.21`。

## 本版变化

### 日程数据

- 新增同槽重复日程合并：预约卡、图文和文字识别结果在同一主播、时间槽和直播间信息一致时合并为一张日程。
- 单人场次也参与去重；标题冲突时保留预约卡官方标题，并合并结束时间与全部自动来源。
- 不会合并能够证明为不同直播间的合法并行场次，也不会删除手动锁定的日程。
- 下一次完整刷新后，历史遗留的同槽重复日程会自动合并。

### 更新渠道与宿主机代理

- 服务端设置页提供正式版与测试版更新渠道，测试版渠道同时比较两端清单并选择更高版本。
- 从测试版主动切回正式版后，服务端立即检查最新正式版并返回可更新状态，由客户端询问是否安装。
- 当目标正式版低于当前测试版时，只允许用户显式确认的手动降级；自动检测和定时更新仍只安装更高版本。
- 宿主机更新代理支持“测试版 → 较低正式版”的受控降级，并继续执行镜像摘要校验、数据备份、健康检查和失败回滚。
- 本次发布将正式版镜像同步更新到 `latest` 和正式版签名清单。

### 服务端 Web 设置页

- 同步桌面端设置页的吸顶标题、文案精简、更新渠道胶囊和 3 秒自动消失提示。
- B 站登录卡片显示服务端登录状态；自定义配色区域只在选中后出现。
- 思考程度改为下拉选择，“关闭”对应原先的“自动”行为。

## 数据、配置与兼容性

- 不改变数据库结构或默认配置，无需数据迁移。
- 不新增必须配置的环境变量；降级授权仍只由宿主机更新代理在手动操作路径中处理。
- 如需要使用“测试版切回较低正式版”的受控降级，请先把仓库中的 `scripts/oshical-updater-agent.sh` 和 `scripts/update-server.sh` 同步到宿主机并重新安装或自检更新代理。
- 正式版签名清单、测试版清单、HMAC 校验和镜像摘要规则保持兼容。

## 升级前操作

1. 备份数据库、环境变量和反向代理配置：

   ```bash
   cp data/oshical.db data/oshical.db.bak
   cp .env .env.bak
   ```

2. 如需受控降级能力，更新宿主机上的 `scripts/oshical-updater-agent.sh` 与 `scripts/update-server.sh`。

3. 重新安装或自检宿主机更新代理：

   ```bash
   sudo bash scripts/install-oshical-updater.sh
   sudo bash scripts/install-oshical-updater.sh --check
   ```

4. 部署 `0.3.29` 镜像后确认 `/api/health` 返回的版本为 `0.3.29`，并检查更新代理在线状态。

## 回滚

- 自动更新失败时，宿主机更新代理会恢复更新前的数据备份和旧镜像。
- 手工回滚前先停止服务，避免数据库仍写入时覆盖数据文件。
- 可重新部署上一正式版镜像并恢复对应的数据库与环境配置备份。

## 已知限制

- 合并不会覆盖无法证明为同一场的并行直播间记录。
- 历史重复需要等待刷新后才会消失。
- 受控降级依赖新版宿主机更新代理脚本；旧脚本仍拒绝较低稳定版目标。
- 镜像构建、签名清单、真实容器重启和自动回滚由 GitHub Actions 与目标宿主机部署流程验证。
