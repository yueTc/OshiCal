# 推历 OshiCal 桌面端 0.3.23-beta.2 测试版

本版基于 `0.3.23-beta.1`，加入完整的 YouTube 主播支持，并同步合入共享核心的同步、迁移、日程和直播统计修复。服务端配套候选为 `0.3.31-beta.1`；本版仅发布到测试版渠道，不发布正式版。

## 新增与体验变化

- 设置页最下方新增“开启 YouTube 功能”总开关，默认关闭。关闭时隐藏 YouTube 添加入口和主播卡片，停止 YouTube 搜索、直播探测、社区帖抓取、统计采样和 OAuth 刷新，但保留已有数据及已保存凭据。
- 主播库支持按平台独立展示 B 站和 YouTube 卡片，不做跨平台人物合并；支持 YouTube 关键词搜索、频道 URL、`@handle`、Channel ID 和关联账号。
- 支持抓取 YouTube 公开社区帖和有权限的会员限定社区帖，并复用现有 LLM 文本/图片分析生成日程。会员 Cookie 缺失、过期或无权访问时跳过会员帖，不把整轮刷新判为失败。
- 支持 YouTube 预约直播、开播/下播检测、开播通知、最近直播和直播场次；直播中与结束后可查看订阅数、当前观看人数、峰值/平均观看人数、直播时长、弹幕、Super Chat/Super Sticker 和会员数。
- 每个最终用户需要自行填写 YouTube API Key。Google OAuth 用于直播聊天和 Super Chat 统计；网页会话 Cookie 用于会员限定社区帖。两者均为可选能力，状态和错误会在设置页明确显示。
- 修复 YouTube 关联账号同步删除时丢失平台、OAuth 刷新与退出竞态、社区帖来源指纹随时间漂移、会员预览图片可能进入分析，以及聊天统计在进程重启后重复累计的问题。

## 数据、配置与兼容性

- 数据库启动时会自动完成 YouTube 相关迁移前检查；旧列集或中间测试版列集需要迁移时，先生成 `*.youtube-v3-backup-*.bak` 一致性备份，再在事务内补齐列、表和索引。迁移失败会停止继续使用半迁移数据库。
- 实时同步协议升级为 schema 3。旧客户端连接新版服务端时应提示升级，不得按 schema 2 解析；JSON 快照协议仍为 `SERVER_SNAPSHOT_SCHEMA_VERSION=1`。
- YouTube API Key、OAuth refresh token 和网页会话 Cookie 使用加密存储，接口只返回“已配置”状态，不回显原文。桌面端保存于系统凭据存储；服务端使用 SecretVault 和独立主密钥。
- 服务端推荐使用 `0.3.31-beta.1` 或兼容 schema 3 的版本。升级前请备份客户端完整数据目录，本地模式至少包括数据库及必要的 `-wal`、`-shm` 文件；服务器数据请由服务器管理员另行备份。
- YouTube Data API、聊天、Super Chat 和会员帖能力依赖用户自己的 API Key、OAuth 和 Cookie；配额、权限、登录态或上游页面变化时，相关指标会显示不可用或跳过，不会伪造为零。

## 下载、安装与渠道

- 版本与标签：`0.3.23-beta.2` / `desktop-v0.3.23-beta.2`，仅发布到测试版渠道，Release 标记为 prerelease，维护固定 `desktop-beta` 清单，不移动正式版清单或 Docker `latest`。
- 普通用户下载 Windows x64 **NSIS 安装包** `OshiCal_0.3.23-beta.2_x64-setup.exe`。已安装用户可在“设置 → 软件更新”切换到测试版渠道并检查更新。
- 自动更新包使用 Tauri 签名校验；当前发布工作流未配置 Windows Authenticode 代码签名，Windows 仍可能提示“未知发布者”。请只使用本项目 Release 或客户端内的更新来源。
- 测试版渠道同时读取测试版和正式版清单，按 SemVer 选择较高版本，不后台降级；用户主动切回较低正式版时，界面必须明确提示并按二次确认执行。
- 构建、签名、测试和产物发布均通过 GitHub Actions 执行。仓库当前不配置 Authenticode 证书；实际签名状态以 Release 产物和 Actions 日志为准。

## 升级前操作、已知限制与回退

1. 升级前备份完整客户端数据目录及服务器连接配置；本地模式退出客户端后备份 `%APPDATA%\com.oshical.desktop`，包括数据库及必要的 WAL/SHM。服务器管理员同时备份数据库、主密钥文件和配置。
2. YouTube 社区页当前只解析首屏，不抓取 continuation 多页；预约直播只检查最近 20 个上传；没有统一搜索/频道元数据 TTL 缓存，频繁搜索会消耗用户自己的 API 配额。
3. `streamers.mid` 当前仍为全局唯一，尚未迁移为 `(platform, mid)` 复合唯一约束；跨平台同名 ID 的极端情况仍有限制。
4. Super Chat 明细以本地历史为主，跨设备只同步场次级聚合；聊天 continuation token 不跨进程持久化，但已用持久消息 ID 去重避免重启后重复计数。
5. 相对发布时间仍按本次抓取时点估算；社区帖首次升级后可能发生一次来源重算。聊天事件表暂无独立清理策略，长期使用会增加数据库体积。
6. 本版是测试版，真实 Google OAuth、Data API、会员 Cookie、Windows ACL、安装升级和 YouTube 专用 UI 仍需按验证文档继续验收。回退时先保存当前数据，再安装上一测试版或恢复升级前备份；旧客户端不能解析 schema 3 同步缓存。

正式版需在本测试版完成验证后另行确认，本次不发布正式版。
