# 服务端 0.3.30-beta.6（测试版）

本版相对 0.3.30-beta.5，修复无预告开播错误关联历史卡片，并统一日程与直播统计的场次身份。配套桌面客户端为 0.3.22-beta.3。

## 新增与修复

- 主播直接开播且没有合适预告时，自动生成“开播补录”卡片，下播后保留；不再无条件把今天的直播高亮到昨天或更早的卡片。
- 新场匹配范围为实际开播时间前后 2 小时（含边界），排除取消、已占用及明确属于其他直播间的卡片；相同时间差按较早预告、较小卡片 ID 稳定选择。
- 平台开播时间未变时复用原场；同主播同直播间在断流 30 分钟内（含边界）恢复、即使平台重置开播时间，也继续关联原卡片和统计场次。跨午夜持续直播不拆卡。
- 连续离线检查不延长断流合并窗口，请求失败不作为下播。未采集到下播时也不会因旧场缺少结束标记而无限合并；缺失开播时间时固定首次检测时间，避免反复生成新场次。
- 日程补卡独立于统计与通知开关，仅遵循主播的日程采集开关；重连保留累计统计。已绑定卡片不因标题变化而换绑，迟到采集的同场预告附加来源，保留卡片和用户修改。
- 用户删除或取消本场卡片后，当前场次不会自动恢复卡片，也不会误高亮其他预告。新增日程和直播关联通过现有增量同步发送，Web 页面无需手动刷新日历。

## 数据与 API 兼容性

- 启动时增量新增 live_broadcasts 轻量状态及卡片绑定字段；不批量改写历史日程，也不根据时间接近推造历史绑定。
- LiveStatus 与 LiveSession 响应新增可空 scheduleId，HTTP、Tauri 及同步 v2 使用同一关联；直播数据查询优先实际绑定，未绑定旧统计的兼容查询限制为前后 2 小时，不再采用原先 12 小时宽范围。
- 快照增加可选 liveBroadcasts，导入校验场次归属、时间与卡片关联并重映射数据库 ID；旧快照仍可读取，迁移状态摘要覆盖新增状态。原有历史统计与采样的快照迁移范围不扩大。
- 共用 crates/core 的改动同时作用于配套客户端独立模式。本版无新增必填环境变量，现有模型、代理、凭据和更新代理配置保持不变。

## 已知取舍

- 30 分钟内主动下播再开也可能合并为续播；提前或迟到超过 2 小时可能同时保留原预告与本场补录卡。阈值本版固定，不新增配置项。
- 旧客户端不一定理解新增的明确卡片绑定，建议升级配套桌面版本；仅升级桌面而保留旧服务端，不能获得服务端自动补卡能力。
- 历史未采集的直播与统计不回填。发生请求失败时等待后续有效观测，不把网络错误解释为下播，也不伪造中间数据。

## 适用产物、升级与回滚

- 适用于 server-v0.3.30-beta.6 的 GitHub Actions Linux/Windows 编译产物及镜像 ghcr.io/yuetc/oshical-server:0.3.30-beta.6。
- 本版属于 beta 渠道，Release 标记为 prerelease，维护 server-beta 清单及镜像 beta 标签；不移动 server-latest 或 Docker latest 正式通道。
- 升级前备份完整 SQLite 数据与配置，保留旧镜像、编译产物及更新代理配置。应使用一致性备份，或停服后连同必要 WAL 一并备份，不能覆盖运行中的数据库。
- 回滚前保留当前完整数据；旧版没有新增的绑定与补卡保证。恢复升级前数据库备份会丢失备份之后的新记录，需谨慎选择。本版不自动删除历史日程或统计。
- 构建、回归、签名、产物验证与发布均通过 GitHub Actions 执行；正式版须另行确认。
